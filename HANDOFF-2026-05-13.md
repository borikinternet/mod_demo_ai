### Handoff: стенд FreeSWITCH + SIPp для проверки recovery

#### 0) Цель текущего этапа
- Собираем натурный стенд для проверки штатного сценария FreeSWITCH recovery, описанного в официальной HA-документации SignalWire/FreeSWITCH.
- На первом шаге проверяется не полноценный HA с двумя одновременно работающими узлами, а упрощенный baseline:
  - один FreeSWITCH-процесс принимает звонок от абонента A;
  - FreeSWITCH бриджит звонок на абонента B;
  - на активном звонке FreeSWITCH будет аварийно остановлен через `fsctl crash`;
  - затем тот же FreeSWITCH запускается снова на том же адресе/порту;
  - recovery запускается явно через штатные команды FreeSWITCH.
- PostgreSQL, floating IP, keepalived/corosync/pacemaker и отдельная сетевая синхронизация на этом этапе не используются.
- Проверка `mod_demo_ai` на этом этапе еще не выполняется.

#### 16) Проверка `mod_demo_ai` и исправление восстановления bridged call
- При первой проверке `demo_ai_takeover <uuid> internal` подтвердилось ограничение старой реализации:
  - команда изолировала все recovery-строки, кроме целевого UUID;
  - `sofia recover` возвращал `Recovered 1 session(s)`;
  - восстановленная A-leg не имела восстановленной B-leg для bridge, после чего звонок завершался.
- Дополнительно подтвердилось, что после `fsctl crash` и последующего restart таблица `calls` может быть пустой, даже если в `recovery` остались обе ноги. Поэтому peer leg нельзя надежно искать только через `calls`.
- В `src/mod_demo_ai.c` изменено поведение `demo_ai_takeover`:
  - сначала проверяется target recovery row;
  - peer UUID ищется через `calls`, если bridge row ещё доступна;
  - если `calls` пустая, peer UUID берется из XML `recovery.metadata`, из variables вроде `signal_bond`, `bridge_to`, `originator`;
  - для `sofia profile <profile> recover` оставляются обе recovery-строки target+peer, остальные строки профиля временно изолируются служебной technology;
  - после recovery проверяется наличие обеих active sessions;
  - явный `uuid_media_reneg +<target_uuid>` оставлен только на целевом UUID, чтобы не создавать лишние re-INVITE на peer leg.
- Также исправлена загрузка модуля:
  - `SWITCH_MODULE_DEFINITION` теперь использует `mod_demo_ai`, а не skeleton-имя `mod_skel`;
  - экспортируется `mod_demo_ai_module_interface`, поэтому FreeSWITCH может загрузить `mod_demo_ai.so`;
  - убраны попытка читать `skel.conf`, лог `Hello World!` и регистрация API `skel`.
- SIPp-сценарии `examples/sipp/ha_long_uac.xml` и `examples/sipp/ha_long_uas.xml` расширены:
  - после первого recovery re-INVITE они ожидают второй in-dialog re-INVITE до `5000` ms;
  - если второй re-INVITE приходит, отвечают `200 OK`, принимают `ACK`, делают `rtp_stream="resume"`;
  - если второй re-INVITE не приходит, переходят к прежней длинной паузе.
